# 🏭 프로젝트 코드 개선 상세 내역 (PPT 발표 자료)

이 문서는 기본(Base) 코드에서 최종(Optimal) 코드까지의 변경 사항과 그 **개선 의도(Why)**를 단계별로 정리한 자료입니다.

## 1. AMR 이동 지능화 (Movement & Routing Intelligence)

### 🛠️ 변경 내용 (What)
*   **AS-IS (변경 전)**: 
    *   **유클리드 거리 이동**: 장애물(설비)을 무시하고 직선으로 관통.
    *   **실시간 연산**: 매번 경로를 계산하여 시스템 부하 유발.
    *   **On-Demand Dispatch**: 일이 발생하면 그제서야 AMR을 호출.
*   **TO-BE (변경 후)**: 
    *   **Obstacle Zone**: 설비 구역을 '이동 불가'로 설정.
    *   **Cached Path**: 미리 계산된 최단 경로만 강제 사용.
    *   **Pre-positioning (사전 배치)**: 유휴 AMR을 작업 완료 예정 설비로 미리 이동.

### 💡 개선 의도 (Why)
1.  **물리적 신뢰성 (Reliability)**: 
    *   **(문제점)** 벽을 뚫고 가는 '텔레포트' 이동은 현실성이 전혀 없어 시뮬레이션 결과를 신뢰할 수 없었습니다.
    *   **(개선)** 장애물 회피 로직을 적용하여 **현실 정합성(Reality)**을 100% 확보했습니다.

2.  **연산 효율성 (Zero Overhead)**:
    *   **(문제점)** 수만 번의 이동마다 길찾기 연산을 반복하여 시뮬레이션 속도가 저하되었습니다.
    *   **(개선)** **"Calculate Once, Use Always"** 전략(캐싱)으로 연산 부하를 제거했습니다.

3.  **반응 속도 혁신 (Golden Timing)**:
    *   **(문제점)** 일이 터진 뒤에야 출발하는 방식은 필연적으로 설비가 작업을 멈추고 기다리는 **유휴 시간(Wait Time)**을 발생시켰습니다.
    *   **(개선)** 미래의 일거리를 예측해 미리 움직임으로써 설비가 멈추지 않고 연속 가동되도록 만들었습니다.

### 📂 추가 변경 항목 (Modified/Added)
*   **`pathfinding.py` (추가)**: A* 알고리즘 및 Obstacle Zone 인식 엔진 구현.
*   **`generate_paths.py` (추가)**: 전체 맵의 최단 경로를 계산하여 `path_cache.pkl`로 저장하는 스크립트.
*   **`sim_core.py` (수정)**: `preposition_idle_amr` 함수 로직 변경 (타이밍 윈도우 적용 및 캐시된 경로 사용).

## 2. 설비 선택 전략 최적화 (Routing Strategy)

### 🛠️ 변경 내용 (What)
*   **AS-IS (변경 전)**: 
    *   **Round Robin**: 순서대로 무조건 공평하게 할당. (Blind Strategy)
*   **TO-BE (변경 후)**: 
    *   **Cost Based Routing**: 비용(이동+대기시간)이 가장 낮은 설비를 선택.

### 💡 개선 의도 (Why)
1.  **Total Lead Time 최소화**: 
    *   **(문제점)** Round Robin은 바로 옆 설비가 비어있어도 순서가 아니면 멀리 있는 바쁜 설비로 보내는 **비효율적 할당**을 반복했습니다.
    *   **(개선)** 거리와 대기열 상태를 모두 고려해 **"가장 빨리 처리할 수 있는 곳"**으로 보내도록 하여 전체 공정 시간을 단축했습니다.

2.  **데이터 기반 의사결정**:
    *   **(문제점)** 단순 규칙(Rule-based)은 상황 변화에 대처하지 못했습니다.
    *   **(개선)** 실시간 시뮬레이션 상태(State) 데이터를 분석하여 최적의 의사결정을 내리도록 지능화했습니다.

### 📂 추가 변경 항목 (Modified/Added)
*   **`sim_core.py` (수정)**: `move_to_next_stage_from_output` 함수 내 라우팅 로직을 Round Robin에서 Cost Based로 전면 교체.
*   **`sweep_routing_amr.py` (추가)**: 다양한 라우팅 전략(RR, Shortest Queue, Cost Based)을 비교하고 수익을 검증하는 스크립트.

## 3. 운영 흐름 최적화 (Operational Flow Control)

### 🛠️ 변경 내용 (What)
*   **AS-IS (변경 전)**: 
    *   **Push System**: 자재가 준비되면 무조건 투입. (라인 혼잡 유발)
    *   **Cold Start**: 텅 빈 공장에서 하나씩 투입 시작.
    *   **No Cutoff**: 시뮬레이션 끝까지 자재를 투입.
*   **TO-BE (변경 후)**: 
    *   **CONWIP (Constant Work-In-Process)**: 공장 내 재공품 개수를 **46개**로 제한.
    *   **Bootstrap Start (Warm-up)**: 시작과 동시에 라인에 일정량 투입.
    *   **Feed Cutoff**: 종료 **11,200초 전**부터 투입 중단.

### 💡 개선 의도 (Why)
1.  **시스템 안정화 (Stabilization)**: 
    *   **(문제점)** 무조건 밀어넣는 Push 방식은 병목 구간에 자재가 쌓여 라인이 꽉 막히는 **Deadlock** 현상을 초래했습니다.
    *   **(개선)** 재공품 수(WIP)를 제한(CONWIP)하여 라인에 '숨 쉴 틈'을 주고 흐름을 원활하게 만들었습니다.

2.  **가동률 극대화 (Throughput)**: 
    *   **(문제점)** 텅 빈 공장이 채워지는 동안 설비들이 노는 시간(Ramp-up)이 아까웠습니다.
    *   **(개선)** Bootstrap으로 시작부터 라인을 채워 가동률을 빠르게 끌어올렸습니다.

3.  **손실 최소화 (Loss Reduction)**: 
    *   **(문제점)** 종료 직전에 투입된 자재는 제품이 되지 못하고 폐기되어 **원가 손실**로 이어졌습니다.
    *   **(개선)** Cutoff를 통해 완성될 수 없는 자재는 아예 투입하지 않아 비용을 절감했습니다.

### 📂 추가 변경 항목 (Modified/Added)
*   **`sim_core.py` (수정)**: 
    *   `try_dispatch_from_warehouse_to_A`: MAX_WIP 체크 로직 추가.
    *   `bootstrap_start`: 초기 투입 로직 함수 추가.
    *   `generate_one_job`: 목표 시간 도달 시 투입 중단 로직 추가.
*   **`data_structures.py` (수정)**: `GlobalVariable`에 `MAX_WIP`, `MIN_COMPLETION_TIME` 변수 추가.
*   **`sweep_wip.py` / `ultra_sweep.py` (추가)**: 최적의 WIP 수치(46)와 Cutoff 시간(11,200)을 찾아낸 튜닝 스크립트.

## 4. 평가지표 선정 (Evaluation Metrics Criteria)

### 📊 성능 평가 모델 (Assessment Model)
본 프로젝트의 성공 여부를 정량적으로 검증하기 위해 **수익성, 효율성, 안정성**을 대변하는 5가지 핵심 지표를 선정했습니다.

1.  **Net Profit (순이익)**
    *   **의미**: `(완제품 가치 - 운영 비용)`. 프로젝트의 최종 목표입니다.
    *   **선정 이유**: 기술적 개선이 실제 비즈니스 성과(돈)로 이어졌는지 판단하는 가장 확실한 척도이기 때문입니다.

2.  **Throughput (시간당 처리량)**
    *   **의미**: 단위 시간당 생산된 완제품(Set) 수.
    *   **선정 이유**: 설비 증설과 병목 해소가 실제로 생산 능력(Capa) 증대로 직결되었는지 확인하기 위함입니다.

3.  **Lead Time (제조 리드타임)**
    *   **의미**: `원자재 투입`부터 `완제품 입고`까지 걸리는 총 소요 시간.
    *   **선정 이유**: **Routing(경로)** 및 **Pre-positioning(배치)** 최적화가 물류 속도를 얼마나 단축시켰는지 증명합니다.

4.  **AMR Response Time (이송 반응 속도)**
    *   **의미**: 설비가 'Call'을 보낸 후 AMR이 도착할 때까지의 대기 시간.
    *   **선정 이유**: 물류 시스템의 **민첩성(Agility)**과 유휴 시간 최소화를 평가하는 기술적 지표입니다.

5.  **Value Added Ratio (부가가치 가동 비율)**
    *   **의미**: 전체 리드타임 대비 '실제 가공 시간'의 비율.`(Pure Process Time / Lead Time)`
    *   **선정 이유**: 공장 내 **낭비(Muda)**가 제거되고 운영 밀도가 얼마나 높아졌는지 보여줍니다.

6.  **Machine Util (설비 가동률)**
    *   **의미**: 설비가 전체 공정 시간 중 가동된 시간의 평균 비율.
    *   **선정 이유**: 병목 공정 해소와 **라인 밸런싱(Line Balancing)**을 통해 낭비되는 유휴 시간(Idle Time)이 얼마나 획기적으로 제거되었는지(69.2% → 94.9%) 증명하기 위함입니다.

7.  **AMR Travel Distance**
    *   **의미**: 제품 1개를 만들기 위해 AMR이 이동한 거리의 평균.
    *   **선정 이유**: **A* 알고리즘**과 **레이아웃 최적화**가 불필요한 배회를 줄여 물류 효율성을 얼마나 높였는지(332.6m → 234.2m) 정량적으로 확인하기 위함입니다.

## 5. 설비 배치 및 수량 최적화 (Layout Optimization)

### 🛠️ 변경 내용 (What)
*   **AS-IS (변경 전)**: 
    *   모든 공정(A, B, C, D, E)에 각각 **4대씩** 동일하게 배치. (Uniform Distribution)
    *   배치 좌표가 일렬로 정렬됨.
*   **TO-BE (변경 후)**: 
    *   공정 부하(Workload)에 따라 설비 수량 재배분: `A(5), B(8), C(6), D(5), E(5)`
    *   유휴 공간(`(14, 5)`, `(38, 15)` 등)을 활용해 동선 단축.

### 💡 개선 의도 (Why)
1.  **라인 밸런싱 (Line Balancing)**: 
    *   **(문제점)** 기존의 획일적(4대) 배치는 시간이 오래 걸리는 B공정(40분)에서 필연적으로 심각한 **병목(Bottleneck)**을 유발하여 전체 생산성을 떨어뜨렸습니다.
    *   **(개선)** 이를 해결하기 위해 **'오래 걸리는 곳엔 많이, 빨리 끝나는 곳엔 적당히'** 설비를 배치하여 전체 공정의 흐름 속도를 균일하게 맞췄습니다.

2.  **Fast Track 효과**:
    *   **(문제점)** 설비 간 거리가 멀어 빈 공간(Dead Space)을 이동하는 데 불필요한 시간이 소요되었습니다.
    *   **(개선)** 빈 공간에 설비를 채워 넣고 동선을 최적화하여 이동 리드타임을 단축했습니다.

### 📂 추가 변경 항목 (Modified/Added)
*   **`main.py` (수정)**: `machine_counts` 딕셔너리와 `machine_positions` 배치 좌표를 최적값으로 변경.
*   **`GPT최적설비수.py` (추가)**: 공정별 소요 시간 데이터를 바탕으로 필요 설비 대수를 산출하는 로직 구현.

### 🤖 AMR 수량 최적화 (AMR Count Optimization)
*   **Method (방식)**: 1대부터 30대까지 모든 경우의 수를 시뮬레이션하는 **전역 탐색(Global Sweep)** 수행.
*   **Tool (도구)**: `sweep_routing_amr.py` (**CPU 병렬 처리**로 고속 검증).
*   **Result (결과)**: **9대**일 때 투자 비용 대비 순이익이 정점(Peak)에 도달함을 확인.
    *   *Insight*: AMR이 9대보다 적으면 이송 지연 발생, 많으면 혼잡도 증가 및 비용 낭비 확인. **"9대가 골든 포인트"**임을 데이터로 증명.

### 💡 최종 결론 (Final Verdict)
*   **Main Driver (주요 요인)**: **설비 배치(Layout)**와 **이동 지능화**가 생산량을 2배로 늘려 순이익 2,300만원 증가의 **99%**를 견인했습니다.
*   **Finishing Touch (마무리)**: **Cutoff**는 단순 절감이 아니라, 공장 내 마지막 혼잡을 없애 **유효 생산(Valid Output)**을 늘리고 낭비를 '0'으로 수렴시킨 **수율 혁신** 기술입니다.
