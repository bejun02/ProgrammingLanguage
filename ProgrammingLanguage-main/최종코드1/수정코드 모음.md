## 1. 상세 구현 로직: 그리드(Grid) 및 장애물 설정

공장 전체를 격자(Grid)로 나누고, 설비(Machine)가 있는 위치를 '이동 불가 영역(Obstacle/Blocked)'으로 마킹하여 AMR이 충돌 없이 주행하도록 합니다.

### A. 그리드 시스템 구축 (좌표 이산화)
실수(float) 형태의 좌표를 정수(int) 인덱스의 그리드로 변환합니다.
- **해상도(`resolution`)**: `0.5`로 설정되었습니다. 즉, 실제 거리 **0.5m**가 그리드 **1칸(Pixel)**에 해당합니다.
- **맵 크기**: 가로 60(`x_max`) × 세로 20(`y_max`) 크기의 공장을 `121 x 41` 크기의 격자로 변환합니다. (`60/0.5 + 1`, `20/0.5 + 1`)

**[핵심 코드: `pathfinding.py`]**
```python
class PathFinder:
    def __init__(self, machine_positions, x_max=60, y_max=20, resolution=0.5):
        self.resolution = resolution
        # [1] 전체 맵 크기를 그리드 인덱스로 변환
        self.width = int(x_max / resolution) + 1
        self.height = int(y_max / resolution) + 1
        # [2] 초기화: 모든 칸을 '이동 가능(False)'으로 설정
        self.grid = [[False for _ in range(self.width)] for _ in range(self.height)]
        self.machine_positions = machine_positions
        self._mark_obstacles()
```

### B. 장애물 마킹 (설비 크기 반영)
설비(Machine)의 중심 좌표를 기준으로 **3x2** 크기만큼의 영역을 칠해버립니다(True = Blocked).
- 설비 크기: **가로 3.0, 세로 2.0**
- 마킹 범위: 중심 `(mx, my)`로부터 `±1.5(가로)`, `±1.0(세로)` 범위 내의 모든 그리드 셀을 `True`로 변경합니다.

**[핵심 코드: `pathfinding.py`]**
```python
    def _mark_obstacles(self):
        # Machines are 3x2 size centered at (x, y)
        for m_type, positions in self.machine_positions.items():
            for (mx, my) in positions:
                # [3] 실수 좌표 -> 그리드 인덱스 변환
                gx, gy = self._to_grid(mx, my)
                
                # [4] 설비 크기(3x2)의 절반만큼을 반경으로 설정
                w_half = int(1.5 / self.resolution)  # 1.5 / 0.5 = 3칸
                h_half = int(1.0 / self.resolution)  # 1.0 / 0.5 = 2칸
                
                # [5] 해당 영역 내 모든 셀을 '이동 불가(True)'로 마킹
                for y in range(gy - h_half, gy + h_half + 1):
                    for x in range(gx - w_half, gx + w_half + 1):
                        if 0 <= x < self.width and 0 <= y < self.height:
                            self.grid[y][x] = True  # Blocked
```

### C. 좌표 변환 함수
실제 시뮬레이션 좌표와 A* 알고리즘용 그리드 좌표를 상호 변환합니다.
```python
    def _to_grid(self, x: float, y: float) -> Tuple[int, int]:
        # 반올림(round)을 사용하여 가장 가까운 격자점으로 매핑
        return int(round(x / self.resolution)), int(round(y / self.resolution))

## 3. 삭제된 코드 (Legacy Pathfinding)
고도화된 A* 알고리즘과 캐싱 시스템을 도입하면서, 기존의 단순하고 비효율적인 경로 탐색 코드는 **삭제**되었습니다.

### 3.1 삭제 이유
- **단순 맨해튼 거리(Manhattan Distance) 한계**: 장애물(설비)을 고려하지 않고 단순히 직각 이동 거리만 계산하여, 실제 이동 시 벽을 뚫거나 돌아가는 경로를 예측하지 못했습니다.
- **`is_path_clear`의 비효율성**: 매 이동마다 `0.5` 단위로 스텝을 밟으며 장애물 충돌 여부를 검사하는 방식은 연산 비용이 너무 컸습니다.

## 4. 설비 선택 라우팅 전략 (Routing Strategy) 비교
`sweep_routing_amr.py`에서는 여러 가지 설비 할당(Dispatching) 전략을 테스트하여 최적의 수익을 내는 방법을 찾았습니다.

### 4.1 비교 대상 전략 및 구현 코드

#### A. Round Robin (순차 할당) - **[최종 채택]**
가용한 설비들에게 작업을 **순서대로 하나씩** 나누어 줍니다.
- **논리**: `Slot_Ok` 리스트의 인덱스를 순환(`% len`)하며 공평하게 분배합니다.
- **장점**: 특정 설비에 편중되지 않고 **가장 안정적인 부하 균형(Load Balancing)**을 유지합니다.

```python
if ROUTING_MODE == "round_robin":
    rr = global_variable.ROUND_ROBIN_IDX.get(nxt, 0)
    drop_m = slot_ok[rr % len(slot_ok)]
    global_variable.ROUND_ROBIN_IDX[nxt] = rr + 1
```

#### B. Nearest (최단 거리)
현재 위치에서 가장 물리적으로 가까운 설비를 선택합니다.
- **논리**: `dist(m.output, target.input)`이 최소인 설비 선택.
- **단점**: 가까운 설비에만 작업이 몰려 **병목(Bottleneck)**이 발생하고, 먼 설비는 노는 현상이 발생하여 전체 가동률이 떨어집니다.

```python
elif ROUTING_MODE == "nearest":
    # 거리가 가장 짧은 설비 선택
    drop_m = min(slot_ok, key=lambda tx: sim_core.dist(m.output_port, tx.input_port))
```

#### C. Shortest Queue (최소 대기열)
대기 중인 작업 수(`input_buf`)가 가장 적은 설비로 보냅니다.
- **논리**: `len(x.input_buf)`가 최소인 설비.
- **단점**: 시뮬레이션 환경에서는 AMR 이동 시간 때문에, 대기열이 적어 보여서 갔더니 그사이에 다른 AMR들이 도착해 다시 혼잡해지는 **진동 현상(Oscillation)**이 발생할 수 있습니다.

```python
elif ROUTING_MODE == "shortest_queue":
    drop_m = min(slot_ok, key=lambda x: len(x.input_buf))
```

#### D. Cost Based (비용 기반)
거리(이동 시간)와 대기 시간(Processing Wait)을 합친 총예상 비용을 계산합니다.
- **논리**: `이동 시간 + 대기열 소진 시간 + 현재 작업 잔여 시간`
- **단점**: 계산이 복잡하고, 예측 오차에 민감하여 라운드 로빈보다 성능이 불안정할 수 있습니다.

```python
elif ROUTING_MODE == "cost_based":
    def cost(target_m):
        # ... (이동 시간 + 버퍼 대기 + 잔여 가공 시간 합산)
        return travel_t + wait_t
    drop_m = min(slot_ok, key=cost)
```


## 5. 초기 가속 및 종료 시점 최적화 (Bootstrap & Feed Cutoff)
시뮬레이션의 시작과 끝부분에서 발생하는 효율 저하를 막기 위한 로직입니다.

### A. Bootstrap Start (초기 가속)
시뮬레이션이 0초에 시작하자마자 첫 번째 설비(Machine A)의 개수만큼 작업을 즉시 '원자재 창고'에 생성하고 투입을 시도합니다.
- ** 효과**: 초기 텅 빈 라인을 빠르게 채워 가동률을 조기에 확보합니다.

```python
# sim_core.py
def bootstrap_start():
    """시뮬레이션 시작 시: Warm-up 가속 - 여러 개를 한꺼번에 투입"""
    # [Warm-up] A 설비 개수만큼 동시 투입해서 라인을 빠르게 채움
    num_a_machines = len(global_variable.MACHINES.get("A", []))
    warmup_count = num_a_machines
    
    log(f"[Warm-up] 초기 투입: {warmup_count}개")
    for _ in range(warmup_count):
        generate_one_job() # 창고에 생성
        
    # 이후 즉시 디스패치 루프 실행
    # ...
```

### B. Feed Cutoff (투입 중단)
시뮬레이션 종료 시간이 임박했을 때, **완성되지 못할 원자재의 투입을 원천 차단**합니다.
- **논리**: `남은 시간 < 최소 공정 시간(약 277분)` 이면 투입 중단.
- **효과**: 완료되지 못하고 공장에 남은 재공품(WIP)은 '재료비 낭비(패널티)'로 간주되어 수익을 갉아먹습니다. 이를 방지하여 **약 62개의 낭비를 줄이고 수익을 2만원 가량 증대**시켰습니다.

```python

    # 277분 = 16620초 (2회 사이클 완성에 필요한 최소 시간)

    remaining_time = global_variable.SIM_END - global_variable.now
    if remaining_time < MIN_COMPLETION_TIME:

## 6. 수익 및 운영 최적화: CONWIP (지정 재공품 제어)
**CONWIP (Constant Work In Process)** 제어는 공장 내 활성 작업(Active Jobs/WIP)의 총 개수를 일정 수준(`MAX_WIP = 50`) 이하로 유지하는 핵심 알고리즘입니다.

### A. 논리적 근거 (Little's Law)
$L = \lambda W$ (재공품 수 = 처리량 $\times$ 공정 시간)
- 재공품 수($L$)를 일정하게 고정하면, 불필요하게 늘어지는 공정 시간($W$)을 통제하여 시스템 전체의 처리량($\lambda$)을 안정화할 수 있습니다.
- 무제한 투입 시 발생하는 **AMR 교착 상태(Deadlock)**와 **교통 체증(Traffic Jam)**을 근본적으로 차단합니다.

### B. 구현 코드
`sim_core.py`의 `try_dispatch_from_warehouse_to_A` 함수가 **Gate** 역할을 하여, WIP가 꽉 찼을 때는 문을 닫고, 물건이 빠져나가면(`drop_end`) 문을 엽니다.

```python
# sim_core.py

def try_dispatch_from_warehouse_to_A():
    # [CONWIP Control] WIP가 50개 이상이면 투입 일시 중단
    MAX_WIP = 50 
    if global_variable.active_wip_count >= MAX_WIP:
        return  # GATE CLOSED

    # ... (투입 로직)
    
    # 투입 성공 시 카운트 증가
    global_variable.active_wip_count += 1

def drop_end():

## 7. Strict Path Caching & Fallback (경로 캐싱 검증)
사전에 계산된 경로(`path_cache.pkl`)만을 사용하여 시뮬레이션을 수행하되, 만약 캐시에 없는 경로가 요청될 경우 실시간으로 계산하여 대응하는 안전장치를 마련했습니다.

### A. 구현 코드 (`sim_core.py`)
```python
def dist(a: Tuple[float, float], b: Tuple[float, float]) -> float:
    '''경로 기반 거리 계산'''
    if a == b: return 0.0
        
    # 1. 캐시 확인 (우선 적용)
    if (a, b) in global_variable.path_cache:
        path = global_variable.path_cache[(a, b)]
        return _calculate_path_length(path)
    
    # 2. 캐시 미스 대응 (Fallback Check)
    # 초기에는 RuntimeError를 발생시켜 경로 누락을 확인했으나, 
    # 동적 상황(Layout Change 등)에 대비해 On-the-fly 계산 로직을 예비로 둡니다.
    log(f"Warning: Cache miss {a}->{b}, calculating on-the-fly...")
    path = global_variable.path_finder.find_path(a, b)
    if path:
        # 찾았으면 캐시에 등록하여 다음 번엔 빠르게 처리
        global_variable.path_cache[(a, b)] = path
        return _calculate_path_length(path)
    else:
        return float('inf') # 경로 없음
```

## 8. 시각화 보간 로직 개선 (Path Interpolation)
AMR이 단순히 출발지에서 목적지로 순간 이동하거나 직선으로 가로질러 가는 것이 아니라, **A*로 계산된 상세 경로(Waypoints)를 따라 부드럽게 주행**하는 모습을 시각화합니다.

### A. 핵심 로직 (`visualization.py`)
시간 $t$에 AMR이 어디에 위치해야 하는지 계산할 때, 전체 경로의 길이 대비 진행률(Progress)을 계산하고, 해당 거리만큼 세그먼트를 따라 이동시킵니다.

```python
def _pos_loaded_at_t(runs, t):
    # ... (시간 t가 포함된 구간 탐색)
    
    # 경로(path) 정보가 있는 경우
    if path and len(path) > 1:
        # 1. 전체 경로 길이 계산
        total_len = sum(dists)
        
        # 2. 현재 시간 진행률에 따른 목표 이동 거리 산출
        progress = (t - start_time) / (end_time - start_time)
        target_dist = total_len * progress
        
        # 3. 세그먼트 순회하며 현재 위치 보간
        current_dist = 0.0
        for i, seg_len in enumerate(dists):
            if current_dist + seg_len >= target_dist:
                # 이 세그먼트 위에 있음
                ratio = (target_dist - current_dist) / seg_len
                p0, p1 = path[i], path[i+1]
                # 선형 보간 (Linear Interpolation)
                x = p0[0] + (p1[0] - p0[0]) * ratio
                y = p0[1] + (p1[1] - p0[1]) * ratio
                return (x, y), loaded
            current_dist += seg_len
```
### B. 효과
- **충돌 시각화 방지**: AMR이 설비를 뚫고 지나가는 시각적 오류가 사라짐.
- **현실감 증대**: 복도와 코너를 따라 주행하는 모습이 구현되어 시뮬레이션 신뢰도 상승.
